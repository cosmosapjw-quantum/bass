# BASS background/high-ell bounded executor

Use only after an explicit implementation authorization and a passed code-intake gate.

1. Load canonical contracts, current DAG/gate/claim state, the pinned code snapshot, and
   the one selected node. Refuse mixed-node work.
2. Reproduce/localize the exact failure or missing obligation. Generate at most three
   genuinely different designs and select the smallest scientifically sufficient one.
3. Before editing, declare files, preserved behavior, equations, units/signs, success
   norms/tolerances, tests, invalidated gates, resource budget, and rollback.
4. Apply one coherent change-set with no silent fallback, projection repair, clipping, or
   unrelated cleanup.
5. Validate in order: software -> equation mapping -> invariant/identity -> analytic limit
   -> convergence/stability -> backend equivalence -> independent review.
6. For numerical/convergence/output claims, generate residual/ratio/refinement plots and
   inspect local structure, not only aggregate norms. Seed sign, normalization, closure,
   grid, and tolerance negative oracles where applicable.
7. If review causes a fix, re-enter at the first affected gate. Maximum two repairs per
   failure class; otherwise mark `BLOCKED`.
8. Write receipts, artifacts, negative results, invalidations, and the next single node.

Never unlock perturbation, likelihood, data, or public-release claims in this executor.
